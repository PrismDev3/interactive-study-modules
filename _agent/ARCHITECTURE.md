# ARCHITECTURE — supplement to PROJECT_MAP.md (read that for the module table)

## Core relationships
- Boot: `main.js` → SceneSetup (renderer, city OBJ merge) → Menu → CharacterController.loadCharacter → Combat, Story, HUD, CityLife, Multiplayer.
- Player rig: the `LegoSpidey` part rig (minifig AN4 clips via `_applyMini`), or a GLB via `SKIN_TO_GLB` → `GlbMinifig` (`_pickClip` → `BigfigAnim` / `Retarget`).
- Movement: `CharacterController` (input, state) ↔ `WebPhysics` (pendulum) ↔ `SwingTarget`.
- Input gate: the leaf module `Input.js` (text-entry guard) is used by every key handler. Keep it a leaf.
- Perf: the `Perf.js` profile (low/medium/high/auto) drives `SceneSetup.degrade(n)` and the minimap rate.
- Online: `Net.js` → `Multiplayer.js` ↔ `server/server.js` (rooms, scrypt accounts, host election); `Social.js` ↔ `server/social.js`.
- Story: `Story.js` missions (`call`/`after` arrays) → `Voice.js` (assets/voice manifest or speechSynthesis); `Progress.js` uses localStorage.

## Data / assets
- `assets/anims/{bigfig,minifig}.json` are generated by `tools/an4/export_*.py`. Don't hand-edit them.
- `assets/models/{spidey,chars,minifigs}` and `assets/ui/lego` are DS rips, used as private placeholders (docs/AUDIT.md).

## Cache-busting
Every import carries `?v=N`, and versioned files are served immutable. `tools/bump.mjs` cascades bumps up to index.html.
